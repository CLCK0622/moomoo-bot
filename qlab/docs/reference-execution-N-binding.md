## C12: execution evidence and the sole N reader

`execution_receipts.n_binding.bind_execution_n` consumes the approved first-phase
`reception_v2.bind_formal_n` entry, with the same opaque host, installed snapshot,
run pin and explicit `EVO883_FACTOR` arm. It does not mint such objects, call
`arm_n.project`, infer N, install anything, or declare/write an attempt. Caller
metrics and serialized receipts cannot replace the host objects. No alternative
formal N reader is introduced.

The four frozen member definitions, solo profiles and 77 exact fold records form
308 possible configuration identities. These are slots, not executions or N.
Actual authority evidence must bind the configuration SHA; run/attempt IDs,
contributions, historical nulls and recorded reach must match original rows.
The host's expected producer/run list must enumerate the actual attempts for
the run; all matching rows are compared, including failed and nonfinite retries.
Missing, duplicated or zeroed retries reject. Reported failure outcomes/reasons
remain observations and are retained even on rejection. Their authenticity and
the completeness of the host's run enumeration require C09/C10 original evidence.

An identity-accepted archive with 101 historical unknowns can supply a verified
attempt map while its formal N slot remains null. Only a value returned by the
existing complete formal reader can populate that slot; the design archive
reference, 308 and high-water
1313 cannot. Even a private counterfactual complete reader result leaves
`complete=false`, `runtime_consumable=false` and explicit outstanding actual B,
P4/P7 and C09/C10 reception. A24 here tests only N binding, not the whole
four-member execution family. A22 full runtime integration remains C09/C10.
