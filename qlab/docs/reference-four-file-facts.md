## Four-file facts and P4/P7 evidence

`reference_boundary.read_execution_inputs(root, preparation)` runs the existing
isolated four-file reader and returns an owned `InputRead`. A dictionary, copied
report or self-recomputed SHA cannot construct this capability. The preparation
still checks the original B predicate for all four declared batches before any
file opens. Each file's original bytes are checked before parsing.

`run_execution_result(observation, input_read=read)` binds the owned common-engine
program to those exact observed rows before starting the result worker. The
worker repeats the same binding against the host-pinned fact document before
replaying C03/C04/C05/C06/C07. It does not reopen numerical inputs. Price/ADV
comparisons call C04's amount reader; they introduce no rounding rule. The
receipt preserves each original cell's token hash and original file identity.
Projection E(t), count, three-state quantity and B must match the checked scope.
The actual program's open/close timestamps bound availability; no synthesized
end-of-day time substitutes for a missing open observation.

Cash and rights retain the original event JSON and its byte SHA. Every nonempty
event on a consumed close date needs a matching original-event operation.
`ReferenceExecution.cash_event` delegates to C04 entitlement, available-cash or
unknown-right processing. It never treats a payment date as cash availability,
converts analytical TR to integer cash, or clears an unknown right. Such an
unknown still prevents a complete C07 observation. Empty events and zero prices
are not interchangeable with unknown values.

The no-`input_read` result channel remains explicitly a diagnostic. It cannot
produce an `ExecutionSidecar`. `reference_v3_evidence.prepare_execution_sidecar`
requires both owned inputs and an owned observation. It obtains the original
N reader result directly, checks run/member/fold/configuration/attempt and
performance reach, and records the actual common-engine DAG and isolated replay.
`series.active_series_raw` is the exact canonical JSON byte representation whose
SHA is `active_series_sha256`; neither is a definition-manifest or sidecar hash.
`execution_receipts/schemas/reference-p4p7.schema.json` closes the pending
engineering sidecar. It does not replace the adopted runtime contract.

This phase has no trusted SRC/AUTH market-source reception object or B runtime
publication. Source-receipt hashes remain identities, not approval; the N host
is never repurposed as market-source permission. Benchmark and locked signal
sources also retain separate identities, not implied four-file certification.
All new results carry `seal_pending`, `execution_verified=false`,
`runtime_consumable=false`, and `certifiable=false`. Formal reception rejects
them before numerical reads or execution. Complete N remains null when the
original reader or the actual attempt map is incomplete. A copied sidecar with
edited flags is rejected as unowned. The external-gate delivery ruling and
formal source/reseal acceptance remain separate prerequisites.

The new scope segment names each component and its exact reader sites. Its only
numerical file names are `raw.json`, `rights.json`, `adv.json`, `cash.json`.
Its three fixed contract files retain full SHA pins; no prefixes or directories
are accepted. The old components' `import_graph` and `reader_sites` retain their
original contents and meanings.
