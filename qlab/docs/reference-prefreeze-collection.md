Reference delivery collection (冻结前脚手架)
=========================================

`qlab.dynamic_factor.prefreeze.collection.collect` records four groups:

* `sources.entrypoints` and `sources.shared_modules`: source SHA-256, byte count
  and path for already loaded Python functions/methods and modules. Entrypoints
  also retain module, qualified function name and first source line.
* `read_dag`: the existing runtime observation document and its original byte
  SHA-256. An import graph is not substituted for an actual reading DAG.
* `scope`: the supplied scope document and original byte SHA-256.
* `ledger_B_proofs`: one observation for every expected ledger ID, including
  explicit missing observations when a ledger's proof was not supplied.

The integration caller supplies `source_root`, `evidence_root`, loaded
`entrypoints`, loaded `shared_modules`, the expected `ledger_ids`, and optional
paths `read_dag`, `scope`, `ledger_B_proofs`. Evidence paths are under the explicit
evidence root. Source paths come from the objects' actual code/module locations;
the collector does not import the requested strategy or execute an entrypoint.

The return schema is `EVO884.PrefreezeCollection/v1`. Every file observation has
`path`, `sha256`, `bytes`, and `reasons`; evidence observations additionally have
`document`. Missing files keep hash, byte count and document null. Invalid JSON
keeps the observed raw byte identity and a nonempty reason. Ledger IDs are opaque:
no arm, N, B membership, permission or budget rule is inferred from their names.
The expected ledger list prevents a missing proof from disappearing merely
because a mapping omitted that ledger.

`format_collection(result)` returns deterministic UTF-8 JSON with one final LF.
The collector and formatter create no files, timestamps, seal markers or
acceptance state. The caller may save the bytes in its explicitly chosen evidence
directory. They never write `project-tip`, an authority manifest or a ledger.

The source hash observes current on-disk bytes at a loaded object's location.
It does not prove those bytes equal a worker's loaded code. DAG, scope and B
documents retain their original claims under `document`; a claimed PASS or empty
B is not adopted as a verified fact. This component makes no certification,
completeness or runtime-consumption decision. Missing/invalid evidence is recorded
for the later verifier, not filled with an empty graph, zero, or invented proof.
It does not call the existing seal, permission, N, budget, reader or planner APIs.

Only this new delivery package, its tests and this document are needed. Candidate
`execution.py`, `pipeline.py` and peak/latch state are untouched. The shared
planner remains absent/null; certification belongs to the later implementation
and independent review. No actual source/run evidence is generated by the unit
tests: all evidence documents are synthetic fixtures.
