Frozen v2 engineering increment (EVO-900, blocks 1–5)
===================================================

Base: `10f9cdc5c6aae7b47e8d3a5dd4dcdc18c28ce011`. Development uses a new
branch; the six EVO-899 files and all previously frozen input bytes are retained.
`load_conventions()` now reads the exact frozen v2 interface and companion main
and common profile. Historical versions require explicit paths. The existing
v1 reference registry is rejected for v2; its immutable bytes remain available
for historical regression tests. The separately scheduled block 6 owns the new
EVO-892 registry and producer/sidecar re-sealing, which this increment does not
claim to complete.

`isolation.seal_manifest` closes the input schema and binds field role, date
range, source SHA, dependency lineage, evidence version and receipt timing.
`eligible_day` derives all U64 states before a scorer sees the sorted E(t).
All 16 recipes receive the same names. Ranking uses average ties and the E(t)
denominator; quarantined/unknown names have null ranks. Unexpected nonfinite or
constant scores invalidate the recipe/date rather than dropping names.

Quantity remains three states: VERIFIED_GE50 closes only the quantity gate;
VERIFIED_LT50 requires a supported upper bound below 50 and allows no new tilt;
UNKNOWN freezes additions. Necessary M, valuation, cash and fees remain required.
Producer receipt consistency does not independently certify source facts or the
actual strict count. The original 252 sessions and threshold 50 remain in force.

Explicit selection consumers may project isolated fields out of the blanket
panel halt, retaining the original audit rows and U64 identity. Untagged,
inventory, valuation, rights and cash consumers retain their required blockers.
The fold precheck consumes the same manifest; S0 context binds its hash and the
per-date derivation hashes. Reference profile/window checks additionally reject
other masks and derivations. Runtime DSR/V and complete factor N remain null.
Neither seed 47 nor a book/request high-water mark becomes a formal N floor.
No production ledger is created, reset or migrated by these changes.

Calibration verifies sealed signal-date rank receipts before filtering verified
labels matured inside the original train window. It retains the original
at-least-50 labels and all ten buckets for every recipe; there is no re-ranking,
zero filling, interpolation, bucket merging or deletion of failed dates.

`state_v2` requires inventory, ages, origin, rights, receivables, cash, NAV and
unknown components to persist. Changed fields require source-bound receipts
from the existing order/fee/corporate-action/mark/age contracts. Isolation is not
an event type. Necessary unknown state stops under R2, retaining declarations
and the last state in all 77 fold slots. Optional trade refusal retains only a
computable original M; it does not create forced exits, age exceptions, a QQQ
meta policy or a new initialization/clock.

K5 checks derive possible inventory paths per fold from the original account
initialization, regular signal schedule and pre-performance E(t). They do not
encode the 23/4 candidate groups or use observed zero holdings as an exemption.
The ADP premise closes only inventory originating before registered ledger
initialization; warmup, TR and labels remain unverified. APD/CMCSA event dates
are conditional candidates, not independently verified ex-date facts. Missing
E(t), admission, entitlement or disposal evidence keeps necessary paths null
under R2. No automatic 252-day release or new disposal/valuation rule is added.

VSNT open/close are exact copies from the scoped v1 field receipt `9b5fd1e8…`
and CSV `cde9f7c0…e9d2c3`. The reader checks both hashes, all 128 calendar rows,
source references and positive finite values. These 256 fields are K5 quotes
only; they do not prove entitlement, fractional-share cash, disposal or NAV and
VSNT remains outside U64. Form 8937 tax FMV cannot replace raw_close.

New CLI readouts, all non-certifying and without performance execution:
`pre_score_isolation`, `state_transition_check`, `k5_dependency_check`.
Existing full-suite network guards remain unchanged; live network tests require
the original explicit opt-in, which verification unsets.
