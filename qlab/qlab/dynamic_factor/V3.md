# Frozen v3 consumer contracts (EVO-900)

Default bindings are the official v3 main `53e570f7…949421`, interface
`dd13affd…4d9e0b`, and common profile `0fdf644c…fdf464`. The original v1/v2
bytes and the v2 transition branch remain historical evidence. The 55/61
published changes replay exactly. Source-hash changes do not certify runtime
inputs, a complete factor-arm N, reference V/DSR, or permission to run.

`isolation_manifest` is recognized only at the top level of the consumer request.
V3 `dependency_lineage` contains explicit nodes (`id`, `field`, `parents`, with
optional symbol/date/event/source fields). These enter the original single graph;
opaque hash lists, duplicate identities, missing parents, cycles and unsupported
containers refuse. Only `normalize_dependencies` in the EVO-898 implementation
is extended. The original whole-request quarantine check still precedes grid,
state and NAV acceptance. A pre-grid failure reports R2 and retains all submitted
state declarations, including inventory, rights, receivables and known cash.
Their declared NAV remains evidence, not a verified value.

V3 eligibility also binds a pre-performance `noncash_guard_manifest`. Its complete
U64 catalog distinguishes CLEAR, UNRESOLVED and UNKNOWN; B is derived, never a
hardcoded three-name list. B is excluded before gate values, scores, ranks or
labels. UNKNOWN is excluded from numeric consumers without being called a
verified B complement. GE50, reliable LT50 and UNKNOWN remain separate. All 16
recipes use the same E(t). Signal-date ranks are sealed before mature labels are
filtered, with no future-label reranking or zero padding.

General missing catalog evidence stays UNKNOWN and cannot be bulk relabeled B
to infer an all-QQQ allocation. Only an explicitly source-bound credible event
or candidate can trigger B protection; its underlying event fact can remain
UNKNOWN. UNKNOWN names do not enter the verified count, scores or admission.

**Real B is not sealed.** EVO-883 v18 receipt
`01a18c7b-9344-7219-ae63-da5fda531e72` accepts the registration framework but
explicitly refuses it as a runtime catalog (61 names remain pending).
`ACCEPTED_CATALOG_SHA256=None`; non-synthetic sealing refuses. Synthetic full-U64
catalogs are counterfactual test fixtures and their hashes are labeled separately.
No real strict count, zero-origin proof, or runtime child-price exemption is
claimed. Neither 64 minus three nor a diagnostic price match proves eligibility.

Each primary/meta strategy and each virtual monitor has a distinct zero-origin
receipt. It requires complete explicit inventory, pending-order state, rights,
receivables and necessary-state evidence. An absent component is not zero.
The six closed acquisition routes are buy, pending order, migration, exchange,
in-kind distribution and old rights. Every route checks both prior and proposed
guarded exposure. It never erases an inherited position or creates a sale.
These checks supplement the original execution, age, gain and fee contracts.

Owned numeric boundaries cover scores, labels, calibration, holdings valuation,
cash valuation and orders. They reject B, UNKNOWN and non-universe child names
before an injected numeric reader runs. Economic receipts bind the actual
numeric-boundary invocation, value digest, reader source and guard source;
catalog/hash-only read lists are refused. The static proof inspects guards and
source dependencies, with poison-reader negatives. This is a proof for pinned
owned boundaries and trusted callbacks, not an OS sandbox for arbitrary injected
Python. Real-source and independent acceptance remain required. Reference
producer proofs and block 6 are deliberately deferred, not borrowed from a
strategy's proof.

The typed cash entrypoint is `factor_cash_valuation`; declaring a guard or a
strategy/monitor role also selects this scope in `integer_cash_valuation`.
Generic accounting remains available to legacy receipts and the independent
shadow accounting implementation, labeled `unbound_accounting_only` with
`factor_arm_numeric_scope_checked=false`. It is not a factor-arm no-read proof.
Likewise, pure fee arithmetic is not an acquisition authorization; the v3
voluntary plan checks its guard before calling the fee engine with that guard.

For an explicitly historical v2 scope, the accepted VSNT receipt/CSV can still
provide K5 quotes. V3 refuses that reader before reading its bytes. No quote,
Form 8937 FMV, high/low midpoint or later close supplies an entitlement, disposal
algorithm, fractional cash or spendable account receipt. Old v2 exposures are
not retroactively waived.

Forward events use received information by the signal close. They immediately
add the parent to B. Holdings, old rights, pending buys or unknown/unproven state
cause R2 with the source state preserved. Proven zero related exposure with all
original gates verified continues other paths; detection alone does not stop.
Prior stopped versions do not restart, clocks do not reset, and no automatic
liquidation or D04 age/gain exception is implemented.

Read-only status: `python -m qlab.dynamic_factor noncash_guard_status --input
empty.json` with `{}` in the input file. It emits source-bound engineering
proofs, a null real B seal, and the reason; it grants no runtime authorization.

remain. Only synthetic varying subsets are verified here. Selection-bias
disclosure: availability isolation and the whole-domain B rule can alter
historical selection, with ex-post information; no point-in-time, random
missingness or v1-return-equivalence claim is made.
